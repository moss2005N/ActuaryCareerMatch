# Security Policy

## Supported version

Security fixes are currently made only on the actively developed default branch.
There are no maintained release branches or guaranteed support periods yet.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting/security-advisory feature for this
repository if it is enabled. If private reporting is unavailable, contact the
repository owner through their GitHub profile to arrange a private channel. Do
not put exploit details, credentials, resumes, phone numbers, email addresses,
or other personal data in a public issue.

Include the affected component, reproduction steps, likely impact, and a safe
proof of concept when possible. Do not access another person's data, degrade a
service, or test against systems without authorization.

The maintainer will try to acknowledge a report and coordinate remediation, but
this project does not currently promise a specific response or disclosure
timeline. This policy is not a bug-bounty offer and does not authorize activity
that would otherwise be unlawful or outside systems you own or are permitted to
test.

Dependency alerts, authentication issues, authorization bypasses, exposure of
resume/profile data, unsafe job-source behavior, and deletion failures are all
in scope for responsible reporting.
